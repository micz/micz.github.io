OpenAI Compatible API 連携を使うと、OpenAI の API 形式に従う任意のサーバーに ThunderAI を接続できます。
これには、LM Studio のようなローカルサーバー、DeepSeek、Grok、Mistral AI、OpenRouter、Perplexity のようなホスト型サービス、さらにカスタムまたはセルフホストのあらゆるエンドポイントが含まれます。

API キーが必要 無料オプション おすすめの用途
サービスによる サービスによる(ローカルサーバーは無料) 柔軟性:ローカルサーバー、代替プロバイダー、カスタムエンドポイント

定義済みの設定

ThunderAI には、よく使われる OpenAI 互換サービス向けのプリセットが用意されています。これらのいずれかを使う場合は、プリセットを選んで API キーを入力するだけです:

プリセット 備考
DeepSeek API 高速で低コスト、強力な推論モデル
Grok API xAI の Grok モデル
Mistral API Mistral AI がホストするモデル
OpenRouter API 1 つの API キーで多数のプロバイダーにアクセス
Perplexity API ウェブ検索で強化されたモデルを含む

セットアップ

最も手早いのは Setup Wizard を使う方法です。ThunderAI のウェルカムページ、ツールバーのポップアップ、 または設定ページから開き、OpenAI Compatible API を選んで、サービスを選ぶかサーバーのアドレスを入力し、 モデルを選んで接続をテストします。その後、ウィザードで必要な AI 機能を有効にできます。
手動で設定する場合は、以下の手順に従ってください。

1. ThunderAI の設定を開く

Thunderbird で、ツール → アドオンとテーマ → ThunderAI → 設定 に移動します。

2. OpenAI Compatible API 連携を選択する

Connection Settings パネルで、Connection Type のドロップダウンから OpenAI Compatible API を選びます。

3a. プリセットを使う

お使いのプロバイダーにプリセットがある場合は、Available Services でそれを選んで確定します。ThunderAI がサーバーのアドレス、 "v1" の設定、チャット名を入力し、モデルの一覧を空にします。API キーを入力して、手順 5 から続けてください。

3b. 手動での設定

お使いのプロバイダーが一覧にない場合は、Custom を選んで手動で設定します:

  • Host Address:サーバーのベース URL です。/v1 は含めません。ローカルで動作する LM Studio の場合、通常は http://localhost:1234 です。リモートサーバーのアドレスも使えます。
  • Keep the "v1" compatibility(詳細オプション内、既定でオン):ThunderAI がアドレスに /v1 を追加し、 http://localhost:1234/v1/chat/completions のようになります。プロバイダーのエンドポイントに /v1 の部分がない場合はオフにしてください。

4. API キーを入力する(必要な場合)

OpenAI Comp API Key 欄に入力します。この欄は任意です。LM Studio のようなローカルサーバーでは通常 API キーは不要なので、空のままでかまいません。ホスト型サービスでは有効なキーが必要です。

5. モデルを選ぶ

OpenAI Compatible API Models の横にある Update list をクリックし、一覧からモデルを選びます。

サーバーがモデルの一覧を提供しない場合は、Add manually をクリックし、プロバイダーが指定するモデル名を入力してください。Clear list で一覧を空にできます。

6. 接続をテストする

設定は変更するとすぐに保存されます。保存ボタンはありません。
接続設定の下にあるバーの Test now をクリックし、Thunderbird の許可リクエストが表示された場合は承認してください。 問題がなければ、バーに "Connected — OpenAI Compatible API reachable" と表示されます。 その後、任意のメールを開き、ツールバーの ThunderAI ボタンをクリックしてプロンプトを実行してください。

詳細オプション

Connection Settings パネルの Advanced options をクリックすると、次の設定が表示されます:

  • Keep the "v1" compatibility:手順 3b を参照してください。
  • Chat Name:ThunderAI のチャットウィンドウで AI に表示される名前です。
  • Temperature:0 から 2 の間です。値を大きくすると出力がよりランダムに、小さくするとより的確になります。
  • Extra body data:サービスがサポートしているものの ThunderAI に表示されないオプション用の追加パラメーターを JSON オブジェクトで指定します。 例:{"top_p": 0.9}、または対応しているサーバーで思考モードを無効にする {"chat_template_kwargs": {"thinking": false}}。

これらのオプションは、カスタムプロンプトのページで個々のプロンプトに設定することも、各 AI 機能(Add Tags、Spam Filter、 Summarize、Translate、Calendar Event、Task)の個別接続にある Advanced options ボタンから設定することもできます。

LM Studio — クイックセットアップ

LM Studio は、OpenAI 互換 API を備えたローカルサーバーと、モデルをダウンロード・管理するためのグラフィカルインターフェースを提供します。

  1. lmstudio.ai から LM Studio をダウンロードしてインストールします
  2. LM Studio のモデルブラウザーから、お好みのモデルをダウンロードします
  3. LM Studio でローカルサーバーを起動します
  4. ThunderAI で Custom を選び、Host Address を http://localhost:1234 に設定し、"v1" の互換性はオンのまま、API キーは空のままにして、モデルを選びます

ヒント

  • OpenRouter は、1 つの API キーと 1 つの請求アカウントで多数のモデル(Claude、Gemini、Mistral など)を使いたい場合に最適です。
  • ローカルサーバーを使う場合、パフォーマンスはハードウェアによって決まります。ハードウェアに関するヒントは Ollama ガイドをご覧ください。
  • リクエストが CORS エラーで失敗し、サーバーの設定を変更できない場合は、ThunderAI の設定で Give permission to the current host をクリックしてください ("Problems setting CORS?" の下)。localhost または 127.0.0.1 上のサーバーの場合、Thunderbird はすべてのウェブサイトへのアクセス(<all_urls>)を求めます。
  • ThunderAI が複数のメールを処理している間(Add Tags、Spam Filter、Summarize、Translate)にサービスのレート制限やクォータを超えた場合、処理は自動的に停止し、処理済みのメッセージ数が表示されます。

トラブルシューティング

ローカルサーバーで "Connection refused"

ローカルサーバー(例:LM Studio)が実際に実行されていること、そして ThunderAI の Host Address がサーバーの待ち受けポートと一致していることを確認してください。

"401 Unauthorized" エラー

API キーを確認してください。キーを必要としないローカルサーバーでは、none のようなダミーの値を入力してみてください。空のキー欄を受け付けないサーバーもあります。

モデルの一覧が空

Add manually をクリックし、プロバイダーまたはサーバーのドキュメントに記載されているモデル名を入力してください。

"404 Not Found"、または URL の "v1" が原因のエラー

Host Address の末尾が /v1 になっていないか確認してください。Keep the "v1" compatibility がオンのときは ThunderAI が自動で追加します。プロバイダーのエンドポイントに /v1 の部分がない場合は、このオプションをオフにしてください。
