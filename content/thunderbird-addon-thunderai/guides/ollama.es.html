La integración con Ollama te permite ejecutar modelos de IA localmente en tu propia máquina.
Con una instalación local tus correos nunca salen de tu ordenador: sin clave de API, sin servicios en la nube, sin costes más allá de tu hardware.
Solo necesitas una clave de API si usas la API alojada de Ollama, o un servidor detrás de un proxy que requiere autenticación.

Clave de API requerida Opción gratuita ¿Privado / Local? Ideal para
No (opcional) Sí (completamente gratuito, usas tu propio hardware) Sí (todo se queda en tu máquina) Usuarios preocupados por la privacidad, correos sensibles, uso sin conexión

Requisitos previos

  • Ollama instalado y ejecutándose en tu máquina (o accesible en tu red local)
  • Al menos un modelo descargado en Ollama
  • Thunderbird con ThunderAI instalado

Instalación de Ollama y descarga de un modelo

Si aún no has instalado Ollama:

  1. Descárgalo de ollama.com y sigue las instrucciones de instalación para tu sistema operativo
  2. Abre una terminal y descarga un modelo, por ejemplo:
    ollama pull llama3
    Otras buenas opciones para tareas de correo: mistral, phi3, gemma2
  3. Verifica que Ollama está en funcionamiento:
    ollama list

Configuración de CORS

Las extensiones de Thunderbird se ejecutan en un entorno aislado, así que Ollama tiene que aceptar sus solicitudes. Hay dos formas:

  • Establece la variable de entorno OLLAMA_ORIGINS en moz-extension://* y reinicia Ollama.
  • O da a ThunderAI permiso para acceder a tu servidor Ollama, con el botón Give permission to the current host en los ajustes de ThunderAI (bajo "Problems setting CORS?"), o aceptando la solicitud que aparece al probar la conexión. Para un servidor en localhost o 127.0.0.1, Thunderbird pide acceso a todos los sitios (<all_urls>).

Para configuraciones CORS más detalladas, consulta la página de información sobre Ollama y CORS.

Configuración

Lo más rápido es el Setup Wizard: ábrelo desde la página de bienvenida de ThunderAI, el popup de la barra de herramientas o la página de ajustes, elige Ollama API (Local LLM), introduce la dirección del servidor, elige un modelo y prueba la conexión. Después el asistente te permite activar las funciones de IA que quieras.
Para configurarla a mano, sigue los pasos de abajo.

1. Abre los ajustes de ThunderAI

En Thunderbird, ve a Herramientas → Complementos y temas → ThunderAI → Preferencias.

2. Selecciona la integración Ollama

En el panel Connection Settings, elige Ollama API (Local LLM) en el desplegable Connection Type.

3. Indica la dirección del servidor

Introduce la URL de tu servidor Ollama en el campo Host Address. El valor predeterminado es:

http://localhost:11434

Si Ollama se ejecuta en otro equipo de tu red, sustituye localhost por la dirección IP de ese equipo.

Deja vacío el campo Ollama API Key para una instalación local normal. Solo es necesario para la API alojada en ollama.com, o para un servidor propio detrás de un proxy que requiere autenticación.

4. Elige un modelo

Haz clic en Update list junto a Ollama Models y después selecciona en la lista el modelo que quieres usar.

5. Prueba la conexión

Los ajustes se guardan en cuanto los cambias: no hay botón Guardar.
Haz clic en Test now en la barra bajo los ajustes de conexión y acepta la solicitud de permiso de Thunderbird, si aparece (consulta Configuración de CORS). Si todo está bien, la barra muestra "Connected — Ollama API (Local LLM) reachable". Después abre cualquier correo, haz clic en el botón de ThunderAI en la barra de herramientas y ejecuta un prompt.

Opciones avanzadas

Haz clic en Advanced options en el panel Connection Settings para mostrar los ajustes de abajo. Se adaptan al modelo seleccionado.

  • System Prompt: se envía al inicio de cada conversación, para dar al modelo un rol o instrucciones fijas.
  • Enable thinking: hace que el modelo razone antes de responder. Los niveles de razonamiento disponibles dependen del modelo y aparecen al seleccionarlo. Model default no envía nada y deja decidir al modelo, que en algunos casos razona igualmente: elige Off para desactivar el razonamiento.
  • Temperature: los valores más altos hacen las respuestas más creativas. El valor predeterminado es 0.8; se recomiendan valores entre 0 y 1.
  • Number of context tokens: cuánto texto puede tener en cuenta el modelo. ThunderAI muestra el máximo que admite el modelo seleccionado. Pon 0 para usar el valor predeterminado del servidor.
  • Keep model loaded: cuánto tiempo mantiene Ollama el modelo en memoria tras una solicitud, p. ej. 5m o 30m, -1 para mantenerlo cargado, 0 para descargarlo enseguida. Vacío usa el valor predeterminado del servidor (5 minutos). Auméntalo si Add Tags, el filtro de spam o el resumen automático trabajan con el correo entrante: si no, el modelo se recarga para cada mensaje.
  • Force JSON output: obliga a Ollama a devolver JSON válido, con los modelos que admiten salida estructurada.
  • Extra options: parámetros adicionales para Ollama, como objeto JSON, p. ej. {"top_p": 0.9, "seed": 42} o {"num_predict": 512}.

También puedes definir estas opciones en un solo prompt, en la página de prompts personalizados, y en cada función de IA (Add Tags, Spam Filter, Summarize, Translate, Calendar Event, Task), con el botón Advanced options de su conexión específica.

Consejos

  • El rendimiento depende de tu hardware. Un equipo moderno con al menos 16 GB de RAM maneja sin problemas modelos como llama3 o mistral. Una GPU acelera mucho el proceso.
  • Los modelos pequeños (7B parámetros) son más rápidos pero menos capaces; los más grandes (13B, 70B) dan mejores resultados pero requieren más recursos.
  • Para tareas de correo, mistral y llama3 son opciones populares, con un buen equilibrio entre calidad y velocidad.
  • Si las funciones automáticas (Add Tags, Spam Filter, Summarize, Translate) se detienen por tiempo de espera con un modelo lento, aumenta Special command timeout (ms) en los ajustes de ThunderAI.

Solución de problemas

"Failed to connect" o no hay respuesta

Comprueba que Ollama se está ejecutando (ollama list en un terminal). Verifica que el campo Host Address en los ajustes de ThunderAI coincide con tu instalación de Ollama.

Error de CORS

La variable OLLAMA_ORIGINS no está establecida, o Ollama no se reinició después de establecerla. Repite los pasos de Configuración de CORS, o usa en su lugar el botón Give permission to the current host.

Lista de modelos vacía

Asegúrate de haber descargado al menos un modelo con ollama pull <nombremodelo> y de que Ollama se está ejecutando.

El modelo razona aunque no quieras

Algunos modelos razonan por defecto. Pon Enable thinking en Off en las opciones avanzadas.
