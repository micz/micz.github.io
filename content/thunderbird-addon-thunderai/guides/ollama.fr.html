L'intégration Ollama vous permet d'exécuter des modèles AI localement sur votre propre machine.
Avec une installation locale, vos e-mails ne quittent jamais votre ordinateur : aucune clé API, aucun service cloud, aucun coût au-delà de votre matériel.
Une clé API n'est nécessaire que si vous utilisez l'API hébergée d'Ollama, ou un serveur derrière un proxy qui exige une authentification.

Clé API requise Option gratuite Privé / Local ? Idéal pour
Non (optionnelle) Oui (entièrement gratuit, vous utilisez votre matériel) Oui (tout reste sur votre machine) Utilisateurs soucieux de la confidentialité, e-mails sensibles, usage hors ligne

Prérequis

  • Ollama installé et en cours d'exécution sur votre machine (ou accessible sur votre réseau local)
  • Au moins un modèle téléchargé dans Ollama
  • Thunderbird avec ThunderAI installé

Installer Ollama et télécharger un modèle

Si vous n'avez pas encore installé Ollama :

  1. Téléchargez-le depuis ollama.com et suivez les instructions d'installation pour votre système d'exploitation
  2. Ouvrez un terminal et téléchargez un modèle, par exemple :
    ollama pull llama3
    Autres bons choix pour les tâches e-mail : mistral, phi3, gemma2
  3. Vérifiez qu'Ollama est en cours d'exécution :
    ollama list

Configuration de CORS

Les extensions Thunderbird s'exécutent dans un environnement isolé, Ollama doit donc accepter leurs requêtes. Il y a deux façons de faire :

  • Définissez la variable d'environnement OLLAMA_ORIGINS sur moz-extension://* et redémarrez Ollama.
  • Ou donnez à ThunderAI la permission d'accéder à votre serveur Ollama, avec le bouton Give permission to the current host dans les paramètres de ThunderAI (sous "Problems setting CORS?"), ou en acceptant la demande qui apparaît quand vous testez la connexion. Pour un serveur sur localhost ou 127.0.0.1, Thunderbird demande l'accès à tous les sites (<all_urls>).

Pour des configurations CORS plus détaillées, consultez la page d'information sur Ollama et CORS.

Configuration

Le plus rapide est le Setup Wizard : ouvrez-le depuis la page d'accueil de ThunderAI, le popup de la barre d'outils ou la page des paramètres, choisissez Ollama API (Local LLM), saisissez l'adresse du serveur, choisissez un modèle et testez la connexion. L'assistant vous permet ensuite d'activer les fonctions IA souhaitées.
Pour une configuration manuelle, suivez les étapes ci-dessous.

1. Ouvrir les paramètres de ThunderAI

Dans Thunderbird, accédez à Outils → Modules complémentaires et thèmes → ThunderAI → Préférences.

2. Sélectionner l'intégration Ollama

Dans le panneau Connection Settings, choisissez Ollama API (Local LLM) dans la liste déroulante Connection Type.

3. Définir l'adresse du serveur

Saisissez l'URL de votre serveur Ollama dans le champ Host Address. La valeur par défaut est :

http://localhost:11434

Si Ollama tourne sur une autre machine de votre réseau, remplacez localhost par l'adresse IP de cette machine.

Laissez le champ Ollama API Key vide pour une installation locale standard. Il n'est nécessaire que pour l'API hébergée sur ollama.com, ou pour un serveur auto-hébergé derrière un proxy qui exige une authentification.

4. Choisir un modèle

Cliquez sur Update list à côté de Ollama Models, puis sélectionnez le modèle à utiliser dans la liste.

5. Tester la connexion

Les paramètres sont enregistrés dès que vous les modifiez : il n'y a pas de bouton Enregistrer.
Cliquez sur Test now dans la barre sous les paramètres de connexion et acceptez la demande de permission de Thunderbird, si elle apparaît (voir Configuration de CORS). Si tout va bien, la barre affiche "Connected — Ollama API (Local LLM) reachable". Ouvrez ensuite n'importe quel e-mail, cliquez sur le bouton ThunderAI dans la barre d'outils et lancez un prompt.

Options avancées

Cliquez sur Advanced options dans le panneau Connection Settings pour afficher les paramètres ci-dessous. Ils s'adaptent au modèle sélectionné.

  • System Prompt : envoyé au début de chaque conversation, pour donner au modèle un rôle ou des instructions permanentes.
  • Enable thinking : fait raisonner le modèle avant de répondre. Les niveaux de raisonnement disponibles dépendent du modèle et apparaissent une fois celui-ci sélectionné. Model default n'envoie rien et laisse le modèle décider, ce qui sur certains modèles signifie qu'il raisonne quand même : choisissez Off pour désactiver le raisonnement.
  • Temperature : des valeurs plus élevées rendent les réponses plus créatives. La valeur par défaut est 0.8 ; des valeurs entre 0 et 1 sont recommandées.
  • Number of context tokens : la quantité de texte que le modèle peut prendre en compte. ThunderAI affiche le maximum pris en charge par le modèle sélectionné. Mettez 0 pour utiliser la valeur par défaut du serveur.
  • Keep model loaded : combien de temps Ollama garde le modèle en mémoire après une requête, par ex. 5m ou 30m, -1 pour le garder chargé, 0 pour le décharger aussitôt. Vide utilise la valeur par défaut du serveur (5 minutes). Augmentez-la si Add Tags, le filtre antispam ou le résumé automatique s'exécutent sur le courrier entrant : sinon le modèle est rechargé pour chaque message.
  • Force JSON output : force Ollama à renvoyer du JSON valide, avec les modèles qui prennent en charge la sortie structurée.
  • Extra options : paramètres supplémentaires pour Ollama, sous forme d'objet JSON, par ex. {"top_p": 0.9, "seed": 42} ou {"num_predict": 512}.

Vous pouvez aussi définir ces options pour un seul prompt, dans la page des prompts personnalisés, et pour chaque fonction IA (Add Tags, Spam Filter, Summarize, Translate, Calendar Event, Task), avec le bouton Advanced options de sa connexion spécifique.

Conseils

  • Les performances dépendent de votre matériel. Une machine moderne avec au moins 16 Go de RAM gère sans difficulté des modèles comme llama3 ou mistral. Un GPU accélère nettement le traitement.
  • Les petits modèles (7B paramètres) sont plus rapides mais moins performants ; les plus grands (13B, 70B) donnent de meilleurs résultats mais demandent plus de ressources.
  • Pour les e-mails, mistral et llama3 sont des choix populaires, avec un bon équilibre entre qualité et vitesse.
  • Si les fonctions automatiques (Add Tags, Spam Filter, Summarize, Translate) s'arrêtent sur un délai dépassé avec un modèle lent, augmentez Special command timeout (ms) dans les paramètres de ThunderAI.

Dépannage

"Failed to connect" ou aucune réponse

Vérifiez qu'Ollama est bien en cours d'exécution (ollama list dans un terminal). Vérifiez que le champ Host Address dans les paramètres de ThunderAI correspond à votre installation d'Ollama.

Erreur CORS

La variable OLLAMA_ORIGINS n'est pas définie, ou Ollama n'a pas été redémarré après l'avoir définie. Refaites les étapes de Configuration de CORS, ou utilisez plutôt le bouton Give permission to the current host.

Liste de modèles vide

Assurez-vous d'avoir téléchargé au moins un modèle avec ollama pull <nommodèle> et qu'Ollama est en cours d'exécution.

Le modèle raisonne alors que vous ne le souhaitez pas

Certains modèles raisonnent par défaut. Réglez Enable thinking sur Off dans les options avancées.
