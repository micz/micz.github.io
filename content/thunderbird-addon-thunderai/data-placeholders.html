Adding and using placeholders

Custom placeholders can be added opening the dedicated tab, pressing the button that can find in the ThunderAI options page.

Placeholders can be added using an autocomplete feature when writing a prompt on the custom prompts page.

With the option "Placeholders: Use default value", you can choose whether to use the default value or retain the placeholder when no value is available (for example, an email with no address in the CC field)

A custom placeholder that is disabled in the Data Placeholders page is not replaced in the prompts: it is left as written, as for a placeholder that does not exist.

Limiting the length of the body

Requires ThunderAI 5.2.0 or later.

Like {%mail_headers:<Header-ID>%} and {%additional_text:<Placeholder-ID>%}, the placeholders {%mail_text_body%} and {%mail_text_body_or_selected%} accept a value after a colon: the maximum number of characters to insert.

{%mail_text_body:2000%}
{%mail_text_body_or_selected:4000%}
  • The text is cut to that number of characters, at the end of a word near the limit. [...] is added at the end only when some text was actually cut.
  • Without a limit ({%mail_text_body%}, {%mail_text_body_or_selected%}) the whole text is used, as before, so your existing prompts do not change.
  • If the value is not a positive whole number (for example :abc or :0), the whole text is used. An invalid value never empties the prompt.
  • The limit belongs to the prompt: an "Add tags" prompt can use 2000 characters while a summary prompt keeps 20000. If a prompt uses the placeholder twice with different limits, each one applies its own.
  • It works everywhere placeholders are replaced: the context menu, the toolbar popup, automatic tagging, Summarize and Translate.
  • The autocomplete in the prompt editor inserts the placeholder without a limit: type the colon and the number yourself.

A typical use is keeping long emails within the context window of a small local model, for example with Ollama or a local OpenAI-compatible server. Without a limit, a very long email can exceed the context window, and the model may then ignore part of the prompt or return an error.
